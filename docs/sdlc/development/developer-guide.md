<!-- sdlc:auto:start overview -->
PMS is a project-management system generated by the Quorq AI SDLC platform, delivered as two separate apps in one repo. The frontend is a Vite + React 19 SPA (TypeScript, Tailwind CSS v4, React Router, TanStack Query) containing every approved screen, currently wired to seeded sample data rather than the live API. The backend is a FastAPI 0.115 service backed by SQLAlchemy models and Alembic migrations; auth, invitations, projects and tasks endpoints are implemented, while the remaining endpoints (comments, checklist, labels, notifications) are typed stub placeholders. The backend defaults to a local SQLite file so it runs with no external database, but docker-compose provides Postgres 16 and Redis for the approved architecture (Celery is used for background work such as invitation emails).
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start setup -->
1. git clone <repo> && cd PMS
2. Copy .env.example to .env and fill in values as needed
3. cd backend && pip install -r requirements.txt
4. (optional, for Postgres/Redis) docker-compose up -d db redis-queue
5. alembic upgrade head   # apply schema migrations (see backend/alembic.ini); required before running the app or tests against Postgres
6. uvicorn app.main:app --reload   # starts the API on http://localhost:8000
7. In a new terminal: cd frontend && npm install
8. npm run dev   # starts the SPA on http://localhost:5173
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend: one router per architecture component (currently a single backend.py router mounted in main.py)
- Unimplemented backend routes return a typed StubResponse placeholder (status 'not_implemented') rather than erroring, keeping the OpenAPI schema complete
- Pydantic schemas follow a Create/Update/Out triplet per entity in schemas.py, with from_attributes=True for ORM conversion
- SQLAlchemy models use string UUID primary keys and created_at/updated_at timestamps (models.py)
- All routes except /health, /auth/login and /auth/accept-invite require the get_current_user dependency (JWT bearer); /invitations additionally requires the require_admin dependency
- Database schema changes go through Alembic migrations in backend/alembic/versions/, never Base.metadata.create_all
- Backend defaults to local SQLite (DATABASE_URL env var overrides to Postgres/other)
- Frontend: one module per approved screen under src/screens/, routed through App.tsx's route table
- Frontend shares a UI/icon vocabulary (lib/ui.tsx, lib/icons.tsx) and brand tokens (lib/brand.ts, index.css) across screens
- Frontend auth/session state lives in one module (lib/api.ts) using localStorage, with apiFetch attaching the bearer token and auto-clearing session on 401
- Component tests live beside the component/screen they cover (e.g. App.test.tsx, screens/*.test.tsx); Playwright e2e specs live separately under e2e/
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| pytest fails with 'ModuleNotFoundError: app' | Run pytest from the backend/ directory so pytest.ini's pythonpath = . applies, or set PYTHONPATH to backend/ yourself |
| Frontend SPA calls fail with CORS errors | Set ALLOWED_ORIGINS on the backend to the frontend's origin, or run the frontend on the default dev ports (http://localhost:5173 / http://127.0.0.1:5173) which are allowed by default |
| Schema out of date / missing tables after pulling changes | Run `alembic upgrade head` in backend/ before starting the app or tests; models are not created via create_all |
| Playwright e2e tests hang or fail to start a server | Run `npm run test:e2e:install` first to fetch Chromium, and ensure backend/requirements.txt installs cleanly since playwright.config.ts boots the backend with `pip install -q -r requirements.txt` before running uvicorn |
| Frontend SPA keeps bouncing to /sign-in | api.ts clears the session and redirects on any 401 response (except /auth/login); sign in again to get a fresh token, or check VITE_API_BASE_URL points at a reachable backend |
<!-- sdlc:auto:end troubleshooting -->
