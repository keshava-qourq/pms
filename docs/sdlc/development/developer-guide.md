<!-- sdlc:auto:start overview -->
PMS is a project-management app generated by the Quorq AI SDLC platform, shipped as two independent applications in one repository. The frontend (frontend/) is a Vite + React 19 single-page app implementing the approved, reviewed screens (sign-in, invite acceptance, projects, a project's task board, task detail, and team) using React Router and TanStack Query, styled with Tailwind and a token-based brand system. The backend (backend/) is a FastAPI 0.115 service backed by SQLAlchemy models and Alembic migrations, implementing auth (JWT), invitations, projects, tasks, comments, checklists, labels and in-app notifications, with Celery used for background jobs such as sending invitation emails and task-saved notifications. The backend defaults to a local SQLite file so it runs without any database server, while the approved architecture targets PostgreSQL 16 and Redis (provided locally via docker-compose) for the real deployment.

<!-- sdlc:auto:start setup -->
1. Clone the repository.
2. (Optional) From the repo root, run `docker-compose up -d` to start local Postgres and Redis containers defined in docker-compose.yml.
3. cd backend
4. pip install -r requirements.txt
5. Copy backend/.env.example to backend/.env and fill in the required values for your environment.
6. alembic upgrade head   # applies all migrations in backend/alembic/versions/
7. uvicorn app.main:app --reload   # starts the API; defaults to a local sqlite:///./app.db if DATABASE_URL is unset
8. In a separate terminal: cd frontend
9. npm install
10. npm run dev   # starts the Vite dev server (defaults to http://localhost:8000 as the API base URL unless VITE_API_BASE_URL is set)

<!-- sdlc:auto:start conventions -->
- One router module per architecture component, with one route handler per API-spec endpoint (backend/app/routers/backend.py mounted in app/main.py).
- Primary keys are string UUIDs (str(uuid.uuid4())) stored as String(36) across all SQLAlchemy models.
- Schema changes go through Alembic migrations (backend/alembic/versions/), never Base.metadata.create_all.
- Response schemas are built explicitly in route handlers rather than via model_validate when the wire shape differs from the ORM column (e.g. TaskOut.owner_id maps to Task.assignee_id/owner_id column).
- Almost every route depends on get_current_user for JWT auth; /invitations additionally requires require_admin; /health, /auth/login and /auth/accept-invite are the only unauthenticated routes.
- Side effects after a commit (invitation emails, task-saved notifications) are dispatched asynchronously via Celery's .delay().
- Frontend screens live one-per-module under src/screens/ with a colocated *.test.tsx; shared design-system pieces are centralized in src/lib/ui.tsx, src/lib/icons.tsx and src/lib/brand.ts/index.css.
- Frontend session/auth state and all HTTP calls are centralized in src/lib/api.ts (localStorage-backed token/user, apiFetch wrapper with 401 handling).
- Playwright specs (e2e/*.spec.ts) are kept out of Vitest's collection via the include pattern scoped to src/.
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Backend errors with 'no such table: users' or similar on startup or in tests. | Run `alembic upgrade head` from backend/ before starting uvicorn or pytest; the schema is created only via migrations, not automatically. |
| `npm run build` succeeds but the app fails type checks or a deployment step. | Run `npm run typecheck` (tsc --noEmit) separately, since `npm run build` does not typecheck. |
| Frontend calls to the API fail in the browser with a CORS error. | Set the backend's ALLOWED_ORIGINS env var to the frontend's origin, or use the default dev origins (http://localhost:5173) that app/main.py already allows. |
| Playwright e2e tests fail to launch or hang on install. | Run `npm run test:e2e:install` first to fetch the Chromium browser before `npm run test:e2e`. |
| Running the backend against Postgres instead of SQLite fails to connect. | Start the docker-compose `db` service and set DATABASE_URL to point at it; backend/app/database.py reads DATABASE_URL and falls back to a local sqlite file only when it is unset. |
<!-- sdlc:auto:end troubleshooting -->
