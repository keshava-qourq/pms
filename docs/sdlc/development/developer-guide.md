<!-- sdlc:auto:start overview -->
PMS is a project-management system generated by the Quorq AI SDLC platform, split into two independently run apps in one repo: a React 19 + Vite single-page frontend whose screens were design-approved and currently run on seeded sample data, and a FastAPI 0.115 backend with SQLAlchemy models and Alembic migrations. The backend has real, tested implementations for auth, invitations, projects and tasks (the latter enqueueing Celery notification jobs), while every other route in the API spec is a typed `StubResponse` placeholder. The backend defaults to a local SQLite file so it runs with no database server, and docker-compose provides Postgres and Redis for a fuller local setup.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js (for the Vite 6 / React 19 frontend)
- Python 3.12
- pip
- Docker and Docker Compose (optional, to run Postgres and Redis via docker-compose.yml)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. git clone the repository and cd into it
2. Copy .env.example to .env and fill in any values it defines
3. (optional) docker-compose up -d to start Postgres (db) and Redis (redis-queue)
4. cd backend && pip install -r requirements.txt
5. alembic upgrade head (apply database migrations; the backend also runs this automatically in Docker)
6. uvicorn app.main:app --reload (starts the API on http://localhost:8000)
7. In a separate shell: cd frontend && npm install
8. npm run dev (starts the SPA, default Vite dev server on http://localhost:5173)
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend routes live in one router per architecture component (app/routers/backend.py), with one handler per endpoint declared in the API spec; unimplemented endpoints return a typed StubResponse rather than failing to exist
- Every authenticated route depends on get_current_user (JWT bearer); POST /invitations additionally requires require_admin
- Schema changes go through Alembic migrations in backend/alembic/versions/, never SQLAlchemy create_all
- Models use string UUID primary keys and created_at/updated_at timestamps set via datetime.now(UTC)
- Schemas are paired per entity (e.g. ProjectCreate/ProjectUpdate/ProjectOut, TaskCreate/TaskUpdate/TaskOut) in app/schemas.py
- Side effects that touch external services (Slack/email) are deferred via enqueue_notification to Celery tasks instead of being called inline from request handlers
- Frontend screens are one module per approved design screen under src/screens, built against the shared component/icon vocabulary in src/lib/ui.tsx and src/lib/icons.tsx and the brand tokens in src/lib/brand.ts / index.css
- Frontend auth/session state is centralized in src/lib/api.ts (token/user in localStorage, apiFetch attaches the bearer and clears session on 401); routes are guarded via a RequireAuth wrapper in App.tsx
- Component tests sit beside the component/module they cover (e.g. Project.test.tsx next to Project.tsx); Playwright specs live separately under frontend/e2e
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Frontend requests to the API fail with a CORS error | Set ALLOWED_ORIGINS (comma-separated) on the backend to include the frontend's origin; it defaults to the Vite dev server origins (localhost:5173) only |
| Frontend can't reach the backend or calls the wrong URL | Set VITE_API_BASE_URL for the frontend build/dev server; it defaults to http://localhost:8000 |
| Backend fails or behaves oddly against a stale schema | Run `alembic upgrade head` in backend/ before starting the app or tests; the Docker image does this automatically before starting uvicorn |
| `pytest` can't import `app` | Run pytest from the backend/ directory so pytest.ini's `pythonpath = .` setting applies |
| `npm run build` succeeds but deployment/typing issues appear later | Run `npm run typecheck` (tsc --noEmit) explicitly, since the build step does not typecheck |
| Playwright e2e tests time out starting services | Ensure backend dependencies install cleanly and port 8000/4173 are free, or set E2E_BASE_URL to run against an already-deployed instance instead of a locally booted one |
<!-- sdlc:auto:end troubleshooting -->
