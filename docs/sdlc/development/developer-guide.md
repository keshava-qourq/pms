<!-- sdlc:auto:start overview -->
PMS is a project management system generated by the Quorq AI SDLC platform, built as two apps in one repo: a React 19 + Vite single-page frontend with a complete, approved set of screens running on seeded sample data, and a FastAPI 0.115 backend with a SQLAlchemy ORM (SQLite by default, Postgres 16 in production) that implements auth, invitations, projects, and tasks (with comments, checklists and labels), using JWT bearer auth and Celery/Redis for asynchronous Slack/email task notifications.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js (for npm/Vite/React 19 tooling)
- Python 3.12
- pip
- Docker and docker-compose (optional, for Postgres + Redis)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. Clone the repository
2. Backend: cd backend && pip install -r requirements.txt
3. Backend: alembic upgrade head (applies migrations; defaults to a local sqlite:///./app.db if DATABASE_URL is unset)
4. Backend: uvicorn app.main:app --reload (starts the API on http://localhost:8000)
5. Frontend: cd frontend && npm install
6. Frontend: npm run dev (starts the Vite dev server, default http://localhost:5173)
7. Optional: from the repo root, docker compose up -d to run Postgres (5432) and Redis (6379) for a production-like setup; set DATABASE_URL and the Celery/Redis env vars accordingly
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend: one router per architecture component (here, a single backend.py) with one route per API-spec endpoint; unimplemented routes return a typed StubResponse rather than erroring, keeping the service startable with a complete OpenAPI doc
- Backend: one Pydantic schema pair per entity (Create/Update/Out), with blank-field validators on required strings
- Backend: SQLAlchemy models use string UUID primary keys and created_at/updated_at timestamps; schema changes go through Alembic migrations, never Base.metadata.create_all
- Backend: all routes except /health, /auth/login and /auth/accept-invite require the get_current_user JWT dependency; /invitations additionally requires require_admin
- Backend: task-create/update enqueues notification jobs (enqueue_notification) instead of calling Slack/SendGrid inline, so request latency and failures aren't coupled to those services
- Frontend: one module per approved screen under src/screens, each colocated with its Vitest test file (e.g. Project.tsx + Project.test.tsx)
- Frontend: shared component/icon vocabulary lives in src/lib/ui.tsx and src/lib/icons.tsx; brand tokens in src/lib/brand.ts and index.css
- Frontend: routes are guarded by a RequireAuth wrapper that checks isAuthenticated() and redirects to /sign-in, preserving the original destination
- Frontend: session (JWT + user) is stored in localStorage via src/lib/api.ts, with Authorization headers attached automatically by apiFetch
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| `pytest` fails with ModuleNotFoundError: No module named 'app' | Run pytest from the backend/ directory so pytest.ini's pythonpath = . applies, or set PYTHONPATH to backend/ explicitly |
| Frontend requests fail in the browser with a CORS error | Set ALLOWED_ORIGINS on the backend to the frontend's origin (comma-separated); in dev it already defaults to http://localhost:5173 and http://127.0.0.1:5173 |
| Backend starts against an empty/outdated schema | Run `alembic upgrade head` in backend/ before starting uvicorn or the test suite; the Dockerfile's CMD does this automatically |
| API calls return 401 and bounce the user to /sign-in unexpectedly | Confirm the stored JWT from POST /auth/login hasn't expired or been cleared; sign in again via the SignIn screen, which calls setSession() |
| Playwright e2e tests fail to launch a browser | Run `npm run test:e2e:install` first to fetch the Chromium binary |
| Need Postgres/Redis instead of the SQLite/no-broker defaults | Run `docker compose up -d` from the repo root, then set DATABASE_URL to the Postgres connection string before starting the backend |
<!-- sdlc:auto:end troubleshooting -->
